# The store

zemi keeps its state in SQLite: a global database at `<state>/zemi.db` (user-scope memory ledger, skill enabled state, `kv`) and one per project at `<state>/projects/<hash of the trust root>/zemi.db` (`ZEMI_STATE_HOME`, default `~/.local/state/zemi`; the `root` file beside it names the project). A repository's subdirectories and worktrees share its project store.

Reach for the store when the CLI does not expose what you need: totals over many sessions, what a tool call returned, a saved config pick. Reading a session is better through the commands (`sessions.md`). Anything else:

```sh
zemi db "select id, title, updated_at, cost from sessions order by updated_at desc limit 5"
zemi db "select tool_calls.tool, tool_calls.ok from tool_calls join messages on tool_calls.message_id = messages.id where messages.session_id = '<id>'"
zemi db "select id, title from sessions where title like ?1 limit ?2" '%test%' 10
zemi db --global "select key, value_json from kv where key like 'config:%'"
zemi db --global "select id, text, origin from memory order by updated_at desc limit 20"
```

The first argument is the whole query, so quote it; the rest bind to its numbered placeholders - the first is `?1`, the second `?2`, and the number, not the position in the query, picks the argument. Values bind as text; SQLite's column affinity compares them against typed columns, so `'24'` works for an integer column and in `LIMIT`. A placeholder with no argument binds as NULL and an extra argument is ignored, so keep the count right. Text output is an aligned table capped at 500 rows, NULL an empty cell; `--json` prints one object per row and caps nothing. `--global` reads the global store; the default is this project's, and `-C <dir>` reads another project's.

The open is read-only all the way down (`mode=ro` and `query_only`): a write fails, nothing is created or migrated, and a store a running zemi holds is read without waiting on it. One SQLite ceiling survives both: `ATTACH` of a path with no file still makes an empty one. A store this zemi's migrations have not reached is refused: run `zemi health` in its project once to migrate it. A missing store is an error naming its path.

The schema the migrations build, regenerated by `make golden` (the section between the markers is not hand-written):

<!-- schema:begin -->
- `checkpoints` - pre-turn file snapshots /rewind restores
  message_id TEXT pk NOT NULL, session_id TEXT NOT NULL, path TEXT pk NOT NULL, existed INTEGER NOT NULL, link INTEGER NOT NULL DEFAULT 0, content BLOB, created_at INTEGER NOT NULL
- `kv` - small state: saved config picks, reflector claims, leases
  key TEXT pk, value_json TEXT NOT NULL, updated_at INTEGER NOT NULL
- `memory` - memory lines with scope, origin and supersede trail
  id TEXT pk, scope TEXT NOT NULL, text TEXT NOT NULL, quote TEXT NOT NULL DEFAULT '', provenance_session_id TEXT, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL, superseded_by TEXT, origin TEXT NOT NULL
- `memory_ops` - the append-only journal of every memory write, for undo and recall
  op TEXT NOT NULL, id TEXT NOT NULL, ts INTEGER NOT NULL, text TEXT NOT NULL DEFAULT '', prior_text TEXT NOT NULL DEFAULT '', quote TEXT NOT NULL DEFAULT '', session_id TEXT NOT NULL DEFAULT '', hash TEXT NOT NULL DEFAULT '', superseded_by TEXT NOT NULL DEFAULT '', scope TEXT NOT NULL DEFAULT '', origin TEXT NOT NULL DEFAULT '', prior_bytes BLOB, prior_truncated INTEGER NOT NULL DEFAULT 0, prior_existed INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL DEFAULT 0, updated_at INTEGER NOT NULL DEFAULT 0
- `messages` - a session's persisted rows, read back in rowid order; role `tail` holds the verbatim tail a compaction kept
  id TEXT pk, session_id TEXT NOT NULL, role TEXT NOT NULL, parts_json TEXT NOT NULL, created_at INTEGER NOT NULL, row_meta TEXT NOT NULL DEFAULT ''
- `proposals` - memory proposals waiting for a /memory decision
  id TEXT pk, payload TEXT NOT NULL, created_at INTEGER NOT NULL
- `sessions` - one row per conversation (top level) or subagent run
  id TEXT pk, parent_id TEXT, title TEXT NOT NULL DEFAULT '', agent TEXT NOT NULL DEFAULT '', created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL, prompt_tokens INTEGER NOT NULL DEFAULT 0, completion_tokens INTEGER NOT NULL DEFAULT 0, cache_read_tokens INTEGER NOT NULL DEFAULT 0, cache_billed_tokens INTEGER NOT NULL DEFAULT 0, cost REAL NOT NULL DEFAULT 0, last_in INTEGER NOT NULL DEFAULT 0, run_status TEXT NOT NULL DEFAULT ''
- `skills` - the skill index synced at boot: path, source and enabled flag per name
  name TEXT pk, path TEXT NOT NULL, source TEXT NOT NULL, enabled INTEGER NOT NULL, created_at INTEGER NOT NULL
- `todos` - a session's todo list
  id INTEGER pk, session_id TEXT NOT NULL, content TEXT NOT NULL, status TEXT NOT NULL, active_form TEXT NOT NULL DEFAULT '', ord INTEGER NOT NULL, created_at INTEGER NOT NULL
- `tool_calls` - one row per tool call a message carried
  id INTEGER pk, message_id TEXT NOT NULL, tool TEXT NOT NULL, ok INTEGER NOT NULL, created_at INTEGER NOT NULL
